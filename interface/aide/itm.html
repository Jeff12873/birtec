Indicateurs ITM

Cet onglet écrit les indicateurs de l'écran « indicateurs personnalisés » de la GMAO : une requête indicateur (le chiffre, colonne VAL) et sa requête liste (les fiches comptées, colonnes ID, CODE, DESI1, ACTIF et, en option, DATE_INDICATEUR). Le résultat reste du SQL : copiez chaque requête dans la GMAO.

Créer un indicateur

Nouvel indicateur ouvre le formulaire « Nouveau rapport » : choisissez ce qu'on compte (étape 1) et les filtres (étape 3), puis Créer un indicateur ITM. BiRTEC écrit les deux requêtes au format de la GMAO, les essaie et les range ici. Copiez-les dans la GMAO et choisissez-y la fenêtre à ouvrir (indiquée).

Ici : choisissez un indicateur pour copier ses requêtes, le tester, le retoucher à la main (« Enregistrer les retouches ») ou le rouvrir dans le formulaire (« Modifier »).

Ce que BiRTEC vérifie

  • Les deux requêtes ont exactement les mêmes jointures et conditions : le chiffre correspond toujours à la liste.
  • Le chiffre est égal au nombre de lignes de la liste, et une même fiche n'apparaît pas deux fois.
  • L'état de la fiche est filtré (ACTIF = 1 est ajouté s'il manque) : sinon la corbeille serait comptée.
  • Les colonnes attendues par la GMAO sont présentes ; rien n'écrit dans la base.

Pour l'essai sur MySQL, les variables de la GMAO sont remplacées par une valeur d'essai : {{ARBO_FILTRE_…}} par 1=1 (aucun filtre), {{DATE_DEB_MOIS}} par le premier jour du mois. Dans la GMAO, elles gardent leur vrai sens.

Retoucher à la main

Vous pouvez modifier directement les deux requêtes puis Tester. Pour qu'elles restent identiques, préférez modifier la définition puis « Refaire les requêtes ».

Variables

Le bouton Variables décrit les variables de la GMAO (nom, valeur d'essai, description pour l'IA). Les tables comptables sont reconnues seules : toute table qui a ID_X, X, DESI1 et ACTIF. Tout est rangé dans le fichier .birtec ; les indicateurs existants servent d'exemples à l'IA.
