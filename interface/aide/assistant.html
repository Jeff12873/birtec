L'assistant

C'est le point d'entrée pour tout : requêtes SQL, rapports BIRT et indicateurs ITM. À chaque question, BiRTEC lui donne les tables utiles (avec les noms clairs du dictionnaire), les chemins de jointure entre ces tables, les conventions de votre site et les requêtes ou indicateurs déjà écrits qui ressemblent à la demande. Le panneau « Donné à l'IA » montre lesquels.

Comment il mène la discussion

Il suit les Consignes (bouton dans le panneau de droite, modifiables, gardées dans le fichier .birtec). Par défaut : il pose les questions utiles pour cerner le périmètre, propose des compléments à cocher (oui / non), demande les paramètres à choisir au lancement, le logo et la description du rapport, et demande s'il s'agit d'un rapport ou d'un indicateur quand ce n'est pas dit.

  • Les réponses toutes prêtes s'affichent en boutons ; les compléments en cases à cocher, puis Valider.
  • Sous chaque requête : Exécuter, Console, Copier.
  • Sous une description de rapport : Créer le rapport (le rapport est rangé dans l'onglet Rapports).
  • Sous une définition d'indicateur : Créer l'indicateur : BiRTEC assemble la requête indicateur et la requête liste, les essaie sur la base, fait corriger l'IA en cas d'écart, puis range l'indicateur dans l'onglet Indicateurs ITM.

Contrôle des réponses

L'IA réfléchit avant d'écrire une requête (« L'IA réfléchit… »), puis BiRTEC contrôle chaque requête sur la vraie structure : table inexistante, colonne absente de sa table (avec les tables qui l'ont), alias non défini. En cas d'erreur, la réponse est réécrite automatiquement (deux fois au plus) ; la mention « Réponse vérifiée et corrigée » l'indique.

Le contrôle garantit que les tables et colonnes existent, pas que la requête répond exactement à la question : vérifiez le résultat (bouton Exécuter). Plus le dictionnaire (noms clairs, descriptions, liens nommés) est complet, plus l'IA est juste.
