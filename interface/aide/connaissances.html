Connaissances (fichier .ktec)

Tout ce que BiRTEC sait de votre site est rangé dans un seul fichier, d'extension .ktec (par défaut Documents/BiRTEC/connaissances.ktec). Le programme, lui, ne contient aucune donnée : c'est une coquille vide. Copiez le fichier pour le sauvegarder ou pour l'utiliser sur un autre poste (« Autre fichier .ktec » pour l'ouvrir).

Ce qu'il contient

  • Notes : conventions et explications. Une note marquée toujours est donnée à l'IA à chaque question : mettez-y les règles de votre GMAO (format des dates, statuts, tables principales, pièges). Les autres notes ne sont données que si elles parlent du sujet.
  • Tables : la structure de la base. Elle est mise à jour à chaque lecture sur MySQL, et sert à l'assistant même quand la connexion est fermée.
  • Liens : quand la base ne déclare pas ses clés étrangères, BiRTEC les déduit des noms de colonnes (ID_XXX → table xxx) ou les lit dans un tableau importé.
  • Requêtes : celles de vos fichiers .sql et de vos rapports. L'IA s'inspire des plus proches de la question.
  • Fichiers BIRT : rapports modèles, bibliothèques (.rptlibrary), feuilles de style, traductions (.properties), images.

Importer un dossier

Indiquez le chemin d'un dossier : BiRTEC parcourt ses sous-dossiers et range ce qu'il reconnaît.

  • Export de structure (« CREATE TABLE », .sql ou .txt) → tables ;
  • tableau .csv avec les colonnes table source / colonne / table cible → liens ;
  • autres .sql, .txt contenant une requête → requêtes ;
  • .md, .txt, .docx → notes ;
  • .rptdesign → rapports modèles (et leurs requêtes) ; .rptlibrary, .css, .properties → ressources.
Les profils de connexion BIRT (fichiers .xml avec odaPassword) contiennent le mot de passe de la base : ils ne sont jamais importés. Les dossiers techniques d'un BIRT Designer (plugins, configuration…) sont ignorés.

Réimporter le même dossier met à jour ce qui a changé, sans doublons.
