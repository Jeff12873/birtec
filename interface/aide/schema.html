Constellation des tables

Le premier écran de BiRTEC : toutes les tables en bulles, reliées par leurs liens, qui se placent toutes seules (les bulles se repoussent, les liens les rapprochent). À l'arrivée, la vue dézoome pendant que les étoiles s'allument et que les liens se tracent (en raccourci aux visites suivantes).

Plus une bulle est grosse, plus la table a de liens. Sa couleur dit son type :

  • Principale (rose-rouge) : un objet métier, ce qu'on veut voir — RI, DI, FI, machine, pièce, personne.
  • Secondaire (bleu) : le détail rattaché à une principale.
  • Intermédiaire (violet) : une table de liaison entre deux tables ; son nom les réunit souvent (ARTMAC = ARTicle + MAChine).
  • Référentiel (blanc cassé) : une liste de codes (types, familles…).
  • Technique (gris) : journaux, exports, paramètres.

BiRTEC devine le type ; l'administrateur le corrige dans le panneau d'une table (« Type de table »). Les couleurs de sélection restent à part : orange pour le chemin choisi, vert pour la table choisie.

  • Molette : zoomer et dézoomer. Glisser le fond : se déplacer. Glisser une bulle : la déplacer. Tout voir : recadrer.
  • Organiser à la main : avec « Figer en lâchant » (coché par défaut), une bulle déplacée reste là où on la lâche (un point sombre la marque) ; les autres s'arrangent autour. Double-clic sur une bulle figée : la libérer. « Tout libérer » : toutes repartent.
  • Curseurs sous le graphe : Force des liens (les tables liées se rapprochent, seulement dans « Ma disposition ») et Écartement (les bulles se repoussent ; dans une autre disposition, il l'étire ou la resserre, impression comprise). Noms et Descriptions : de combien plus loin (en dézoomant) les noms et les descriptions des tables restent écrits. Clés de liaison : la clé de chaque lien écrite le long de sa ligne (ex. « ID_DI », ou « ID_PERE = ID_ARTICLE » quand les colonnes diffèrent) ; zoomez si une ligne est trop courte pour l'afficher. Reprises à l'impression.
  • Survol d'une bulle : ses tables liées s'éclairent. Les noms apparaissent en zoomant.
  • Clic sur une bulle : c'est la source ; son nom clair, sa description, sa prise en compte par l'IA, ses tables liées.
  • Ctrl + Maj + clic : construire le chemin soi-même, table par table (la première table cliquée est le départ). Si une table n'est pas directement liée à la précédente, le plus court passage entre les deux est ajouté. « Retirer la dernière » revient en arrière.
  • Ctrl + clic sur une autre bulle : le chemin le plus court entre les deux, tracé en orange, avec les tables traversées, les clés de chaque jointure et le SQL à copier. Les tables voisines du chemin restent nettes et nommées : ce sont celles qu'on peut y ajouter.
  • Le chemin préféré : un lien nommé, puis une table de liaison qui réunit justement les deux tables (ARTMAC, faite pour relier ARTICLE et MACHINE, plutôt qu'une autre table qui touche aussi les deux), puis une table « fille ». Quand un autre chemin est presque aussi court, le panneau le propose : « Autre chemin : par … ».
  • Le SQL part toujours de la première table (SELECT * FROM …) et ajoute les jointures dans un ordre que BIRT accepte : chaque jointure ne cite que des tables déjà jointes.
  • Clic sur un lien : le nommer et le décrire. Un lien nommé est préféré pour les chemins (ceux du schéma comme ceux donnés à l'IA).
  • Ajouter un lien manquant (dans le panneau d'une table) : quand une colonne pointe vers une autre table sans suivre la convention ID_XXX.
  • Le cadre Raccourcis, en haut à droite du graphe, les rappelle ; un clic sur son titre le replie.
  • Chercher une table : le graphe se centre dessus. « Tables écartées de l'IA » les montre en grisé.

La disposition « Par types »

Dans le menu des dispositions : l'axe des tables principales au centre, de haut en bas, les voisines rapprochées (en léger zigzag, pour qu'un lien entre deux principales éloignées ne passe pas sur une autre) ; à gauche les intermédiaires, à mi-hauteur des deux principales qu'elles relient, puis les référentiels ; à droite les secondaires, en quinconce autour de leur principale ; en bas les tables techniques.

Le menu des dispositions commence par Ma disposition (la vôtre, gardée dans le fichier .ktec), puis quatre catégories. Utiles : par types, autour de la table choisie, arbre depuis la table choisie (une colonne par nombre de liens qui l'en séparent), hiérarchie, anneaux par importance (par nombre de liens), amas, familles de noms, grille alphabétique. Fantaisies : cercle, spirale, étoile, cœur, fleur, vague. Dynamiques, qui bougent sans cesse : galaxie tournante, orbites par type (chaque anneau tourne à sa vitesse), pulsation, flottement. Impression : tables entières. Une disposition ne fait que montrer : la vôtre n'est jamais modifiée.

Autour de la table choisie : la table choisie au centre, puis un cercle par type de table, du plus métier au plus technique : principales, intermédiaires, secondaires, référentiels, techniques. Les principales sont ordonnées pour que les plus liées soient voisines ; sur les cercles suivants, chaque table est posée à l'angle des tables qu'elle relie (une table de liaison, entre les deux tables qu'elle relie), juste écartée de ses voisines : les liens restent courts.

Tables entières (catégorie Impression) montre toutes les tables, même les tables écartées et les liaisons masquées, chacune dans sa propre case d'un quadrillage taillé pour une feuille A3 : aucun nom ne chevauche un autre. Les principales sont réparties en blocs, les plus reliées côte à côte ; chaque autre table est posée au plus près de ce qu'elle relie ; les tables sans aucun lien sont rangées en bas. Choisissez-la, puis Imprimer ou Constellation en PDF.

LA PHRASE

Le bandeau au-dessus de la constellation se construit par des choix, sans IA : Je souhaite consulter les [la table], puis des conditions « qui [ont, n'ont pas, contiennent, ne contiennent pas, commencent par, finissent par, ont plus que, ont moins que, ont entre] [la table] [le champ] [la valeur] ». Sans valeur, « ont » veut dire que le champ est rempli (la table liée existe), « n'ont pas » qu'il est vide. La table est celle qu'on consulte, une table principale, une table secondaire reliée (ex. les mouvements de stock) ou un référentiel relié directement (liste de codes : avancement, type…) ; la jointure est ajoutée toute seule. Pour les valeurs, celles de la base sont proposées en tapant.

Un champ de date a ses propres choix, après le champ : le [jour], avant le, depuis le, entre le … et le …, dans les derniers [3] [jours, semaines, mois, années], il y a plus de [1] [année…], ou pendant [aujourd'hui, hier, cette semaine, la semaine dernière, ce mois-ci, le mois dernier, cette année, l'année dernière]. Les durées et les périodes se recalculent chaque jour : un rapport enregistré « des 3 derniers mois » suit le calendrier. Les dates de la GMAO sont rangées en AAAAMMJJ ; une date vide n'est jamais comptée « avant » une autre.

+ et qui… ajoute une condition à remplir aussi ; + OU un autre cas ouvre un cas de plus : chaque cas est une carte (« Cas 1 », « Cas 2 »…) et une ligne est gardée si elle remplit un des cas, c'est-à-dire toutes les conditions de ce cas. Un clic sur un ET sépare le cas en deux à cet endroit ; un clic sur le bandeau OU réunit les deux cas. ( groupe ) ajoute des conditions lues ensemble, entre parenthèses. Pour l'ordre, cliquez sur une colonne de l'aperçu : croissant, puis décroissant, puis sans tri ; Maj + clic ajoute un tri secondaire. La pastille + à côté de la première colonne de chaque table ouvre ses colonnes à cocher (la colonne de la jointure ou d'une condition reste affichée) ; chaque table ajoutée a sa couleur. Une condition peut aussi s'arrêter à la table (« qui ont » [table], sans champ) : une ligne liée existe dans cette table. Le chemin s'allume dans la constellation, un entonnoir marque chaque table filtrée, et le nombre de lignes et un aperçu suivent chaque choix. L'administrateur voit aussi « Voir le SQL pour BIRT ».

Quand une condition porte sur une autre table, un menu par … montre par où passe la jointure (par exemple RI → Pièce par les mouvements de stock, ou par les pièces prévues d'une fiche) ; l'administrateur fixe un passage pour toutes les phrases avec le cadenas. La pastille + qui… au bout de la condition ajoute des conditions sur cette table (« des pièces qui ont telle famille »).

Les choix guidés demandent le modèle de données du site (Configuration › Modèle de données). En mode administrateur, la roue à côté du champ choisit les colonnes proposées pour chaque table : les utilisateurs ne voient que celles-là.

Sous les jointures : Créer un rapport (le formulaire déjà rempli d'après la phrase), Enregistrer le SQL (rangé dans les requêtes du site) ou Indicateur GMAO. Le chemin et la phrase sont gardés avec le rapport ou l'indicateur, pour le rouvrir plus tard dans la constellation.

Extraire pour Excel

Télécharger la table (la table choisie) ou, après un chemin, Extraire pour Excel : un zip avec le dossier sources (un CSV par table, entière), analyse.xlsx (une requête Power Query par CSV, en chemin relatif : le classeur reste juste où qu'on dézippe le dossier), constellation.png (le tracé seul, sur fond blanc : les tables du chemin dans l'ordre des jointures, tables de liaison comprises même si elles sont masquées, le nom de chaque lien ; pour l'administrateur, les clés et le SQL) et un lisez-moi. Dézippez sur un disque local (pas dans OneDrive ni SharePoint) et ouvrez analyse.xlsx : Données › Requêtes et connexions.

La constellation en PDF

Constellation en PDF (en haut) enregistre directement un fichier PDF dans le dossier des téléchargements : une page A3 paysage sur fond blanc avec tout le graphe tel qu'il est disposé, le nom de chaque table, le chemin choisi en surbrillance avec ses clés, et une légende. Imprimer envoie la même page à l'imprimante. Disposez d'abord le graphe à votre goût : le PDF reprend la disposition à l'écran.

Tout ce qui est saisi est gardé dans le fichier .ktec, y compris la disposition des bulles : elle est retrouvée à chaque ouverture et reprise par l'impression.
